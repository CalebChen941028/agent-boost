This report answers one question with metered live traffic: with the same model as the brain, what changes when the engineering toolchain around it is added or removed? Five executable engineering tasks — drawn from the failure archetypes of **BugsJS**, **SWE-bench / SWE-bench Verified**, and **HumanEval-X** — ran as a real dual-track duel:

- **Solo mimo-v2.6-flash (control)**: one model, bare prompts, no tools. No file-conflict gate, no Git rollback, no reproduction-test synthesis, no lifelong memory, no independent judge.
- **mimo-v2.6-flash + agent-boost (treatment)**: the same brain driving the v0.4.0 five-phase state machine — `evaluateTaskComplexity` compute tiers, `matchExperienceCues` recall, `detectTargetFileConflicts` ownership gating, per-workstream execution, LATS Git checkpoints with real `git reset --hard` rollback, `verify_synth.sh` test synthesis, and `calculateYardstickScore` six-criterion judging.

The harness is [`scripts/run-live-benchmarks.mjs`](scripts/run-live-benchmarks.mjs). Run `npm run benchmark` (or `npm run benchmark:live`) and the same machinery places real HTTP calls from your own account. Offline, run `npm run benchmark:selftest` to verify all 21 harness mechanisms with zero API spend.

## 1. Methodology, Stated Precisely

> [!IMPORTANT] Read this before reading any table
> 1. **What runs.** Real network round-trips to the live gateway. Every code artifact was generated by the model over HTTP; every token figure below is the gateway's own `usage.prompt_tokens` / `usage.completion_tokens` metering (mimo is a reasoning model — its completion budget covers chain-of-thought before visible content); every latency is a measured wall-clock round-trip; every exit code comes from a real `node --test` process in an isolated temp Git workspace.
> 2. **Fairness protocol.** Identical task briefs, identical fixture repositories, identical immutable test suites, identical judge prompt. Solo may retry up to 3 attempts with raw failing-output feedback; boost repair budgets come from `evaluateTaskComplexity` (simple 2 / standard 3 / hard 5) — the compute-tier allocation itself is part of the treatment. The fixture test suite is a frozen specification for both arms: workstream plans that declare test-file ownership are stripped, and the suite is restored before every test run, so neither arm can ever grade itself against a rewritten suite.
> 3. **Ground truth.** Tasks with a fixture suite are scored by it directly. The no-verify-command task (`LIVE-REST-SYNTH`) is scored by a hidden post-hoc test appended to both workspaces only after both arms declare completion — the solo arm's claim "done, no test command configured" is never contradicted during its run, which is exactly the scenario under test.
> 4. **The judge.** Both arms are scored by the same agent-as-a-judge call (independent review of the delivered diff plus final test outcome). Findings feed `calculateYardstickScore`; the pass gate is ≥ 85 with zero high-severity findings. In this run every judge verdict parsed from the model (no deterministic fallback fired).
> 5. **What this run does not show.** Rollback counters. Zero `git reset --hard` fired because no repair round in the final protocol regressed a baseline-passing test — the model's fixes were clean on all five tasks. The rollback mechanism itself is real (executed and evidenced in the protocol-calibration runs; see Section 6) but was not needed here. That is the honest reading: on these five tasks the treatment's wins came from coordination and verification, not from repair heroics.

## 4. Task Narratives — What Actually Happened Over the Wire

### A. `LIVE-EXPRESS-RACE` — the decisive contrast

Two feature teams extend a shared Express-style gateway (`src/server.js`) in parallel; the acceptance suite requires both route groups mounted. The solo arm models an uncoordinated parallel harness: two concurrent live calls per round, each subagent emitting its own full `src/server.js`, whichever settles last wins the file. Across all three permitted rounds the metrics team's write replaced the auth team's registration — every round ended `pass=1 fail=1`, failing test `gateway mounts OAuth2 auth routes`, exit 1 after 6 calls and 4,281 metered tokens. No amount of retrying recovers work that the next concurrent write deletes.

The boost arm's Phase 1 planner initially proposed an overlapping partition; `detectTargetFileConflicts` rejected it and the replan converged to a single integration workstream owning `src/server.js`. First verify run: `exit=0 pass=2 fail=0`, delivered diff 4 lines added, score 100/100, zero repair rounds. Verbatim from the log:

```text
Track A (solo):   [solo race r1..r3] exit=1 pass=1 fail=1   (6 calls, 4,281 tokens)
Track B (boost):  [boost P1] conflict gate: intercepted 1 overlap(s)
                  [boost P3] verify: exit=0 pass=2 fail=0   (first pass, 2,041 tokens)
RESULT: solo FAIL (exit 1, score 84) vs boost PASS (exit 0, score 100)
```

### B. `LIVE-SEMVER-REGRESSION` — the strong-solo case, stated honestly

A pre-release hyphen-range bug in a semver comparator whose naive fix breaks caret-range and build-metadata baselines. **The bare model solved it in one shot**: one call, 2,312 tokens, 6/6 tests green, judge score 100, no regression. The boost arm also passed (scoped 24-line comparator fix, hard tier allocated 5 repair rounds, used 0) at 1.9x the solo token cost. This row is the report's control: on a single-file algorithmic fix inside one context, the toolchain adds process, not outcome.

### C. `LIVE-REST-SYNTH` — verification where none is configured

A v3→v4 customer-payload transformer; the repository declares no verify command (`verifyCommand: null`); legacy producers send `billing_address: null`. The solo arm implemented it in one short call (417 tokens) and declared completion with **zero executable checks** — its claim was only ever tested by the hidden post-hoc suite appended after both arms finished. The boost arm detected the missing command, synthesized a 145-line reproduction test (`verify_synth.sh` path) — syntax-validated via `node --check` before it may ship — and verified 11 assertions in-phase (null mapping, field order, missing-field fallbacks, type guarantees) before declaring anything. Final ground truth for the boost workspace ran 13 tests (11 synthesized + 2 hidden), all green. Same delivered outcome, different epistemic status: one arm knew it worked before shipping; the other found out afterwards.

### D. `LIVE-TOKENIZER-BOUNDARY` and E. `LIVE-RATELIMIT-RACE` — boundaries a strong model clears solo

A streaming tokenizer whose escape-streak state must survive chunk boundaries, and a sliding-window limiter whose check-then-set must complete synchronously. The bare model fixed both first-try (5/5 and 3/3 tests, judge 100), as did the boost arm. Two notes worth keeping: Phase 1 recalled accumulated experience cues (2 cards each) from earlier tasks in the run — memory participation is real but did not change these outcomes; and in both tasks the planner's initial workstream plan again declared invalid ownership (a test file), which the ownership gate stripped before any edit.

## 5. What the Live Data Says the Toolchain Buys

1. **Coordination is the decisive win.** The only task requiring two writers to share one file is the only task the solo arm lost — deterministically, three times in a row, while burning 2.1x the boost arm's tokens on doomed retries. `detectTargetFileConflicts` converted that failure into a first-pass pass at planning time. All five boost tasks entered execution with gated, conflict-free ownership.
2. **Verification changes what "done" means.** On the no-verify-command task the solo arm's completion claim was unexecutable by construction; the boost arm shipped with 11 self-synthesized, syntax-validated assertions already green. The hidden ground truth happened to agree with both — but only one arm knew that at delivery time.
3. **A strong solo baseline is reported as such.** mimo-v2.6-flash one-shot four of five tasks. On single-file algorithmic fixes, the deterministic suite's 0/12-vs-12/12 margin does not transfer to live single-agent use — the live margin on this suite is one task (the coordination task), plus epistemics on the unverified-synthesis task.
4. **The metered price.** 1.677x total tokens (fewer inputs, 3.79x outputs — mimo reasons more across more roles), ~2x mean per-call latency, ~2.4x wall time. Planning, judging, and verification are real API spend, now metered rather than modeled.
5. **Zero rollbacks is a result, not a absence.** The LATS machinery (real `git reset --hard`, reflog evidence) exists and executed during protocol calibration (Section 6); in the final run the model simply never regressed a baseline. The tool's value is conditional insurance — it costs a checkpoint and fires only when needed.

## 6. Harness Integrity Protocol (and What Calibration Taught)

The final protocol was hardened through three live calibration runs (sessions `be328743`, `cf88a811`, `Bwgjef`-series); their artifacts are not counted in this report's numbers. Each calibration exposed a real leak, fixed before the definitive run:

| Leak observed in calibration | Fix now enforced in the harness |
| :--- | :--- |
| A body-read with no deadline hung the run for 12 minutes on a trickling response | Whole-request deadline covering headers and body; per-call retry/backoff on 429/5xx/network errors |
| A boost workstream declared `test/*.test.js` files as ownership and polluted ground-truth discovery (suite drifted 6→9 tests) | Ownership gate strips all test-path declarations on every plan and replan; suite restored and stray test files purged before every run |
| Repair scope was limited to `sourceFiles`, leaving a broken workstream-owned module unreachable by repair | Repair scope = every workstream-owned file |
| Regression was defined as "more failures than baseline", misfiring on seeded-bug target tests and looping rollbacks | Regression = a test that **passed on the pristine fixture** now fails; checkpoints advance only through non-regressing states |
| A workstream rewrote a working fixture module to import `express` (dependency-free repo) | KEEP_BASE discipline in the execution prompt: existing files satisfying their contract are emitted unchanged; no npm imports |
| A synthesized test arrived truncated at max_tokens (SyntaxError) and shipped broken | `node --check` validation before shipping; one doubled-budget re-synthesis; a still-invalid script is discarded and the arm proceeds unverified — never a broken verify artifact |

The calibration runs also exercised the rollback path for real (`git reset --hard` fired twice on genuine baseline regressions in session `be328743` before the regression definition was corrected), which is why Section 2 can report zero rollbacks as a measured outcome rather than an untested path.

## 7. Reproduction Guide (Run the Live Duel Yourself)

### One command

```bash
export OPENCODE_API_KEY=oc_sk_...   # opencode.ai console key (Go plan); also read from ./.env or ~/.env
npm run benchmark                   # full 5-task duel, ~10–15 min, ≈ $0.005 at mimo list price
npm run benchmark:selftest          # zero API spend offline verification of all 21 harness mechanisms
```

The runner prints every request's outcome, token metering, and test scoreboard; append `--json out.json` for the structured ledger (every HTTP call with latency, status, and usage). Harness machinery can be verified with zero API spend: `npm run benchmark:selftest` (21 checks: every fixture fails on its seeded bug, canonical fixes go green, Git reset/reflog round-trip, verify-gate invariants).

### The task prompts, adapted for mimo-v2.6-flash

The two worked examples from the previous edition, now matching the live suite's task text verbatim (both are `LIVE_TASKS` entries in [`scripts/run-live-benchmarks.mjs`](scripts/run-live-benchmarks.mjs)):

```text
Fix a bug in the semver range comparator module src/semver.js exporting satisfies(version, range).

Bug: satisfies("1.2.3-alpha.1", "1.2.0 - 1.2.4") must return true.

Required rule: a pre-release version satisfies a hyphen range iff its core version
(prerelease tag dropped for the bound comparison) lies within the bounds AND its
[major, minor] pair equals the [major, minor] pair of at least one bound.

Constraints — these existing behaviors must keep working (regressions are not acceptable):
  satisfies("1.2.4", "^1.2.3") === true
  satisfies("1.3.0", "^1.2.3") === true
  satisfies("2.0.0", "^1.2.3") === false
  satisfies("1.2.4-alpha.1", "^1.2.3") === false   // prerelease excluded from caret ranges
  satisfies("1.2.3", "1.2.3+build") === true        // build metadata ignored
  satisfies("1.2.0", "1.2.0 - 1.2.4") === true
  satisfies("1.2.5", "1.2.0 - 1.2.4") === false
  satisfies("1.3.0-alpha", "1.2.0 - 1.2.4") === false (out of bounds)
```

```text
Write the transformer in src/transformers/v3-to-v4.js exporting transformCustomer(payload)
that maps a v3 customer payload { id, billing_address: { line1, city } | null } to the v4
shape { id, line1, city }. Legacy producers intermittently send billing_address: null;
the output must then be { id, line1: "", city: "" }.

The repository has no test command configured.
```
